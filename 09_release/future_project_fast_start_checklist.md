# Future Project Fast Start Checklist

## Intake Questions

Ask these before donor work starts:

- What is the project name, game name, game ID, game type, target RTPs, volatility, min/default/max bet, coin/denomination model, and known target layout?
- Is donor feature/settings parity strict, approximate, or intentionally divergent?
- What donor authorization mode applies: observation-only, authorized internal scaffold capture, or licensed release asset reuse?
- Should scaffold assets be captured for internal scene previews?
- Is a public or private sanitized review export required, and what repository/path should be used?
- What current GS source roots, registration/config roots, runtime roots, and candidate lane roots are explicitly allowed?
- What secret references exist, and where should raw secrets never be stored?
- Is safe demo/test mode available, and how will it be confirmed before spins?

## Fast-Start Skill Order

1. ProjectCreator.
2. AuthorizedReferenceResearcher with donor feature/settings parity and gameplay observation.
3. ReferenceAssetInventory with authorized scaffold capture, hashing, ownership classification, and scene asset gap analysis.
4. ProtocolAndSchemaMapper current-GS lane, registration, RNG, and math ownership audit.
5. MathModelDesigner layout alignment, simulator trust audit, and math/result contract.
6. Pause for review before scene mapping or builder planning.

## Pause Criteria

Pause and ask for review when donor feature/settings evidence is incomplete, current GS result owner is unproven, registration import boundary is unknown, math layout does not match donor/product direction, or public export validation
fails.
